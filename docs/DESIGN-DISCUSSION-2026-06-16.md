## 一、核心决策：从引擎架构转向多 Agent 协作架构

### 为什么必须改

| 旧架构问题 | 根因 | 新架构解决方式 |
|-----------|------|--------------|
| 引擎无协同，各自输出独立 JSON | 引擎设计为独立运算单元 | Agent 互相读取对方结论，交叉审查后再输出 |
| 分析不作用于创作（"体检报告不治病"） | 输出是 JSON 报告，不是可应用的修改 | Agent 直接产出内联修改建议，作者点击即替换 |
| 分析太慢（N 次 LLM 调用） | 每次全量调用所有引擎 | HCP-MAD 渐进式：简单问题 2 Agent 一致即过，复杂才升级 |
| 架构僵化，加一个能力要改 5 个文件 | 注册式架构（prompts+config+router+SHARED+frontend） | Agent 插件化，自描述，注册一处生效 |
| 堆砌代码（"屎山"） | 无统一的 Agent 基类和协作协议 | 统一基类 + 标准协作协议 + 清晰的生命周期 |

### 新架构原则

1. **概念保留，实现重生**：PAD 模型、伏笔追踪、语域检测等概念全部保留，但从 System Prompt + JSON 输出改为 Agent 协作模式
2. **作家是最终裁决者**（Co-DIRECT Director-in-the-Loop 范式）：所有 Agent 建议经过总编 Agent 排序后推给作家，低置信度自动丢弃
3. **异构认知多样性**（Hermes Council 原则）：不同 Agent 使用不同分析镜头，互相审问推理过程而非仅仅比较结论
4. **渐进式升级**（HCP-MAD 三级模型）：不每次都调全部 Agent，按需升级

## 二、Agent 全景：9 个 Agent

### 8 个领域 Agent + 1 个总编 Agent

| # | Agent 名称 | 分析镜头 | 旧引擎映射 | 核心能力 |
|---|-----------|---------|-----------|---------|
| 1 | **角色 Agent** | 角色心理 | Character Engine | PAD三维情感、行为模式一致性、社会关系感知 |
| 2 | **世界 Agent** | 虚构法则 | World Engine | 规则校验、空间一致性、力量体系 |
| 3 | **叙事 Agent** | 故事结构 | Narrative Engine | 伏笔生命周期、因果链质量、情节节奏 |
| 4 | **文辞 Agent** | 语言质感 | Prose Engine | 句长/语域/修辞、角色对话风格匹配 |
| 5 | **主题 Agent** | 作品意义 | Theme Engine | 主题提取+强度追踪、主题-意象映射 |
| 6 | **经济 Agent** | 物质流动 | Economy Engine | 资源追踪、经济行为-角色动机关联 |
| 7 | **预期 Agent** | 读者心理 | Reader Expectation | 信息不对称建模、悬念强度、反转铺垫 |
| 8 | **构思 Agent** | 意象象征 | Conception Engine | 意象注册+演变追踪、意象密度分析 |
| 9 | **总编 Agent** | 综合裁决 | (新增) | 冲突裁决、优先级排序、整体质量判断 |

### 关键设计：总编 Agent

总编不分析文本本身，它的输入是其他 8 个 Agent 的结论：

1. **冲突裁决**：两个 Agent 结论矛盾 → 总编判断 + 给出置信度
2. **优先级排序**：8 个 Agent 产出若干条建议 → 过滤次要、合并重复、按"对作品质量提升幅度"排序
3. **低置信度自动丢弃**：置信度低于阈值的建议不推给作家
4. **检测到僵局时**：暴露完整 Agent 讨论链 + 分歧地图给作家裁决

## 三、Agent 协作协议

### 协作模式 A：并行 → 交叉审查（作家触发"帮我看看这段"）

```
第 1 轮（并行分析）:
  根据任务类型选择 2-4 个 Agent → 各自独立产出初步结论

第 2 轮（交叉审问 · Hermes Council Probe 模式）:
  每个 Agent 读取所有其他 Agent 的第 1 轮结论
  → 追问推理过程："你为什么得出这个结论？你的依据是什么？"
  → 修正自己的结论（如果被说服）

第 3 轮（仅当冲突无法自动解决时触发）:
  总编 Agent 介入 → 裁决或暴露分歧给作家

作家收到:
  合并后的内联修改建议（不是独立报告）
```

### 协作模式 B：链式接力（作家触发"帮我续写"）

```
叙事 Agent → 角色 Agent → 文辞 Agent → 主题 Agent（审查）
  情节方向     角色反应     文字润色     一致性检查
```

### 自适应升级机制（HCP-MAD 启发）

```
简单任务（如"这段语域正确吗"）:
  文辞Agent 本地规则引擎先跑 → 偏差<阈值 → 直接返回 → 0次LLM调用

中等任务（如"这个角色行为合理吗"）:
  角色Agent + 叙事Agent 并行分析 → 结论一致 → 返回 → 2次LLM调用

复杂任务（如"帮我检查整个场景"）:
  4+ Agent 并行 → 交叉审问 → 总编裁决 → 6-8次LLM调用
```

## 四、交互 UX 设计

### 核心交互流

```
作家在编辑器中写作
  │
  │  被动模式：写够 500 字，后台自动触发轻量检查
  │  ↓
  │  有问题 → 编辑器中出现黄色小圆点 (●)
  │
  │  作家点击小圆点
  │  ↓
  │  圆点展开 → 替换文字直接出现在编辑器中
  │  · 替换文字高亮显示（建议色，不挡住原文）
  │  · 原文保留在原位，标记但不变色
  │
  │  作家操作:
  │  ├─ 双击替换文字 → 直接替换原文
  │  ├─ 右键 → 退回小圆点状态
  │  └─ Ctrl+左键 → 展开详细 Tips
  │                   ┌──────────────────────┐
  │                   │ 角色Agent: 理由...    │
  │                   │ 文辞Agent: 理由...    │
  │                   │ 置信度: 0.82         │
  │                   │ [查看Agent讨论▼]     │
  │                   └──────────────────────┘
```

### 设计原则

- 不阻挡原文（修改建议和原文同时可见）
- 建议文字和原文用不同颜色/样式区分
- 最小打扰（被动模式只显示圆点，不弹窗不中断）
- 作家完全掌控（每一条修改都需要作家确认才生效）

## 六、模型分配策略

| Agent | 推荐模型 | 理由 |
|-------|---------|------|
| 叙事 Agent | Pro | 需要深度多章节推理 |
| 角色 Agent | Pro | 需要复杂心理分析 |
| 总编 Agent | Pro | 需要综合多 Agent 判断 |
| 主题 Agent | Pro | 需要抽象文学理解 |
| 文辞 Agent | Flash | 本地统计为主，LLM 辅助 |
| 世界 Agent | Flash | 规则匹配为主 |
| 经济 Agent | Flash | 逻辑简单，主要是比对 |
| 预期 Agent | Flash | 比对为主 |
| 构思 Agent | Flash | 模式识别为主 |

### 关键降本策略

- **本地规则引擎优先**：统计类分析（句长、对话占比、词汇重复率）用纯 Python，不调 LLM
- **仅异常时调 LLM**：偏差 < 阈值直接跳过，偏差 > 阈值才把问题段落 + 基线数据发给 LLM
- **渐进式升级**：简单问题 2 Agent，复杂才全调
